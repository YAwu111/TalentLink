# 运行日志设计

> 对应代码：`backend/app/core/logging.py`、`backend/app/middleware/request_log.py`

## 1. 为什么要做

排查线上问题最痛苦的不是报错，而是**报错之后无法还原现场**：不知道是哪个请求、哪一步、哪个用户触发的。
所以日志设计的核心目标只有两条：

1. 一次请求的所有日志能用**同一个 ID** 串起来
2. 错误日志能独立成文件，不被业务日志淹没

## 2. 日志去向

| 输出 | 内容 | 用途 |
|---|---|---|
| 控制台 | 全部级别 | 开发时实时观察 |
| `backend/logs/app.log` | INFO 及以上 | 完整流水，按天切分，保留 14 天 |
| `backend/logs/error.log` | ERROR 及以上 | 只放异常，出问题时直接看这个文件 |

轮转策略使用 `TimedRotatingFileHandler(when="midnight", backupCount=14)`，
即每天零点切分一次，历史文件自动带上日期后缀，超过 14 天自动删除。

## 3. 日志格式

```
2026-11-04 10:39:27 | INFO    | 1f562a56cb6a | talentlink.auth | 登录成功 id=2 username=hr_xinghe role=employer
     ↑ 时间            ↑ 级别     ↑ 请求ID        ↑ 模块            ↑ 消息
```

| 字段 | 说明 |
|---|---|
| 时间 | 精确到秒，本地时间 |
| 级别 | DEBUG / INFO / WARNING / ERROR |
| 请求 ID | 12 位十六进制，同一请求内所有日志共享；无请求上下文时为 `-` |
| 模块 | `talentlink.access`（访问）、`talentlink.auth`（认证）等 |
| 消息 | 建议使用 `键=值` 形式，方便人读也方便 grep |

## 4. 请求 ID 的传递

```
浏览器请求
   ↓
RequestLogMiddleware：读取 X-Request-ID，没有则生成 12 位随机串
   ↓ contextvars 写入
业务层 / 依赖 / 线程池中的同步函数（anyio 会自动复制上下文）
   ↓
每条日志自动带上该 ID（logging.Filter 注入 record.request_id）
   ↓
响应头回传 X-Request-ID，前端报错时可直接报给后端排查
```

**排查方式**：拿到前端报错里的 request_id，执行

```bash
grep 1f562a56cb6a logs/app.log
```

就能看到这次请求从进入到返回的全部记录（鉴权、SQL 慢点、业务分支、异常栈）。

## 5. 已覆盖的日志点

| 场景 | 级别 | 位置 |
|---|---|---|
| 每个 HTTP 请求（方法、路径、状态码、耗时、IP） | INFO | 中间件 |
| 健康检查 / 文档请求 | DEBUG（默认不输出） | 中间件 |
| 注册成功 | INFO | `auth_service.register` |
| 登录成功 / 失败（含原因） | INFO / WARNING | `auth_service.authenticate` |
| 刷新令牌轮换 | DEBUG | `auth_service.rotate_session` |
| **刷新令牌被重用**（疑似盗用） | WARNING | `auth_service.rotate_session` |
| 用户登出 | INFO | `auth_service.revoke_session` |
| 请求参数校验失败 | WARNING | 全局异常处理器 |
| 未捕获异常（含完整堆栈） | ERROR | 全局异常处理器 |

参数校验失败与未捕获异常的响应体里都会带上 `request_id`，用户截图报错即可精准定位。

## 6. 配置项（`.env`）

```ini
LOG_LEVEL=INFO        # DEBUG 可看到健康检查等高频请求
LOG_DIR=logs          # 相对后端起服务的工作目录
LOG_TO_FILE=true      # 置 false 则只打控制台
LOG_BACKUP_DAYS=14    # 历史日志保留天数
```

## 7. 与前端日志的关系

前端不做上传，只在浏览器控制台留下两类痕迹：

- React 组件渲染异常：`ErrorBoundary` → `[react-error <时间>]`（含组件栈）
- 未捕获的 Promise 异常：`[promise-error <时间>]`

浏览器 DevTools 的 Network 面板能看到每个响应的 `X-Request-ID`，
把前端现象与后端日志对上，是这套设计真正省时间的地方。
