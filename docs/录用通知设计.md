# 录用通知设计

## 1. 业务规则

- 企业可以对同一求职者发多个 Offer
- 求职者可以同时收到多个待回应 Offer
- 求职者只能接受一个 Offer
- 接受一个 Offer 后：
  - 该 Offer 变为 `accepted`
  - 其他待回应 Offer 自动变为 `declined`
  - 其他对应投递变为 `offer_declined`
  - `seekers.accepted_offer_id` 写入唯一 Offer ID
- 已被接受的 Offer 不能被企业撤回
- 已接受其他 Offer 的求职者，不能被再次发送 Offer

## 2. 状态

### OfferStatus

```text
sent ──接受──> accepted
  │
  ├──求职者拒绝──> declined
  └──企业撤回──> revoked
```

### ApplicationStatus

```text
submitted
  └── viewed
        └── interview
              ├── offered
              │     ├── offer_accepted
              │     └── offer_declined
              └── rejected
```

- `offered`：已发 Offer，等待求职者回应
- `offer_accepted`：求职者已接受
- `offer_declined`：求职者拒绝，或因接受其他 Offer 自动失效
- 企业撤回 Offer 后，投递回到 `interview`，可重新发 Offer

## 3. 唯一性约束

`seekers.accepted_offer_id`：

- nullable
- UNIQUE
- 不建外键，避免 `seekers ↔ offers` 循环依赖；由服务层维护引用一致性

接受操作在一个事务内完成；如果并发接受两个 Offer，唯一约束会让其中一个失败，接口返回 409。

## 4. 接口

### 企业

```http
POST /api/employer/applications/{application_id}/offer
POST /api/employer/applications/{application_id}/offer/revoke
```

发放/修改请求：

```json
{
  "salary": 16000,
  "start_date": "2026-12-01",
  "message": "欢迎加入"
}
```

- 只有 `submitted / viewed / interview / offered(sent)` 可以发放或修改
- 已有 `sent` Offer 时再次 POST 表示修改条件并重新发送
- 企业撤回后可在 `interview` 状态重新发放

### 求职者

```http
GET  /api/seeker/offers
POST /api/seeker/offers/{offer_id}/accept
POST /api/seeker/offers/{offer_id}/decline
```

求职者 Offer 返回：

- 企业/岗位/城市
- 薪资、入职日期、说明
- Offer 状态、发送/响应时间
- 对应投递状态

## 5. 接受事务

```text
校验 Offer 属于当前 seeker
校验 Offer.status == sent
校验 seeker.accepted_offer_id IS NULL
写入 Offer.accepted + responded_at
写入 Application.offer_accepted
写入 seeker.accepted_offer_id
其他 sent Offer -> declined + offer_declined
commit
```

失败回滚，不会出现“接受了一半”的状态。

## 6. 前端

- 企业投递详情：发放/修改/撤回 Offer 弹窗
- 企业投递列表：显示 `已发录用 / 已接受录用 / 已拒绝录用`
- 求职者顶栏新增「录用通知」
- 求职者待回应 Offer：接受/拒绝
- 接受后显示已接受横幅，其他通知进入已处理列表
- 同一求职者再次接受其他 Offer 会被后端 409 拦截

## 7. 当前边界

- 没有 Offer 过期任务
- 没有邮件/站内信通知
- 没有入职确认、背调、合同签署
- 企业撤回已接受 Offer 被禁止
- 撤回后重新发 Offer 复用同一条 Offer 记录
